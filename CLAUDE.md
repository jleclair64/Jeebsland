# Jeebsland

Unreal Engine 5.8 C++ project (Windows). Game code lives in `Source/Jeebsland/`. Most of the world (forest, village, castle, pond, etc.) is built procedurally in C++ actors rather than placed assets.

- Default game mode: `KnightGameMode` (set in `Config/DefaultEngine.ini`); the world is built by `KnightGameState`. Map: `/Game/Field`.
- The UE template code and content (Variant_*, Characters, ThirdPerson, LevelPrototyping, template game mode / controller) were deleted 2026-10-12. `AJeebslandCharacter` stays: it is the knight's base class (camera boom and camera). StateTree plugins are off.
- `Game Updates.txt` is the owner's private notes. Don't read or act on it; requests come through chat.

## Model and effort

The owner wants a recommendation on model and effort for each request, to balance quality against token use. Before executing any large task (or a batch of tasks), always suggest the most optimal model and effort first. "Optimal" means balancing token usage while still getting a great result that won't need rework. For a mixed batch, say which items suit which model. For small requests, one line is enough, and only if it differs from the current setting. Don't switch unless asked.
- Sonnet 5.5, low or medium effort: tweaks to values, colors, sizes or positions; removing things; small single-file changes.
- Sonnet 5.5, high effort: moderate features or multi-file changes along existing patterns.
- Opus 5.5, high effort: new systems (skills UI, enemies, combat, dungeons), tricky visual or rendering bugs, anything Sonnet failed at.

## Ending a session

When the owner says goodbye, goodnight or anything similar, don't just sign off: first ask if they'd like you to commit and refresh the "Current state" notes below for their next chat. If they say yes, update that section (what was just done, what's unfinished, known issues, decisions, anything they want carried over), remove stale lines, keep it to about a screen, and commit. In the same question, also ask whether to repackage the game (only if code or content changed since the last package; then make `Packaged/Jeebsland.zip` without the `.pdb`, and remind them to restart the worlds with `Tools/HostWorlds.bat` and send friends the new zip).

## Hit boxes and hurt boxes (2026-10-31, Smash Ultimate style)

`HitBoxes.h` (namespace JeebHit). Hurt boxes are capsules on the joints (`KnightHurt`: helm, torso, upper arms, forearms, thighs, shins; anything with health can give its own through `UHealthComponent::GatherHurt`, else an upright capsule). Hit boxes are spheres on the weapon, live only in a move's active frames, swept from the last frame, lowest ID wins, one hit per target per move (`AKnightCharacter::TickHitboxes`, server lands the blow). Only the sword's jab uses them so far (`SwordJabBoxes`; its old cone check in `AttackLands` is skipped); new moves should get their own hit box tables and active windows. View: `DrawBoxes`, material M_HitBox (see-through, no depth test); H toggles, on by default in MoveLab only. MoveLab has a still sparring knight (`AFoeKnight::bStill`; `-LabKnight=170` moves him closer for test pictures) and a still guarding one (`bStillGuard`; `-LabGuardFirst` puts him straight ahead, `-LabKnightYaw=0` turns both knights' backs to you). `ShotPos` does not move the player in MoveLab.

Shields, kick and knockdown (owner, 2026-10-31): `TickHitboxes` takes whatever each hit box meets first along its sweep (`FirstTouchWedge` vs `FirstTouch`; a tie goes to the shield): body first is a clean hit (no rebound). A blow on a raised shield never hurts the holder: the guard takes all of it (`Hurt` for players, `AFoeKnight::TakeOnShield`); the blow that empties it breaks the guard and drops the shield until it refills. The kick (`EAtkStyle::Kick`, wheel up, `StartKick`; pose in `PoseKick`, Ken's forward smash mirrored to the right leg) goes through shields and knocks a shielding target down (`UHealthComponent::KnockDown`, `AKnightCharacter::KnockDownBy`; players' kicks hit other players only in MoveLab until PvP). `MoveLocked()` covers the smash lock, the kick and lying down. Knocked-down players get up with `GetUp` (0 up, 1 roll left, 2 roll right). Measured from above: a hip's roll is NEGATIVE to swing the leg out to his right, and an UpperPivot/BodyRoot roll + tips the top to his right (Unreal's roll; an older note here said the opposite). Strafe mode is on from the start (`bStrafeMode = true`). Kick timing (second pass): `KickDur` 0.65 s, active 0.18-0.5; the leg keys in `PoseKick` are ABSOLUTE angles blended in by W (not added to the stance), so the leg goes straight out toward the target with the toes turned to his left; the first hit sphere sits 24 cm past the ankle along the shin, ahead of the sole.

Combat rules and balance (owner, 2026-10-31, second pass): rock-paper-scissors, attack > kick > shield > attack. The jab's hit boxes cover its whole swing (hit 1 0.30-0.80, hit 2 0.36-0.74). The kick knocks anyone down (`UHealthComponent::KnockDown`, `KnockDownBy`) and on a raised shield also crushes half the guard; a kick into a blade that is coming (`BladeComing`, `UHealthComponent::IsSwinging`) loses and the kicker falls; a blow landing during a kick knocks the kicker down (`Hurt`). Hitstun (`StunLeft`, `TakeReact` / `MulticastReact` / `ApplyReact`, `JeebHit::FReact`): jab 1 0.45 s (hit 2 is a sure combo), jab 2 0.32 s with a push clear, smash 0.5-0.8 s; clean blows no longer give 0.4 s of invulnerability (hazards still do). The low sweep (`EAtkStyle::Sweep`, wheel down, sword only, `SweepDur` 0.55, active 0.24-0.6 (out in 0.13 s since the third pass), key poses `Sweep` in PoseArms, tip about 10-15 cm off the floor) launches whoever it hits (`JeebHit::LaunchVelocity`: 450 up, 150 back, DI up to 18 degrees from the held direction, `NoteDI` / `ServerDI`); launched knights land knocked down (get-up waits for landing; `KnockAuto` 1.5 s from landing). The pen knight (`AFoeKnight`) has hitstun (`EAct::Stun`), can be launched (`Launch`, `bAir`), never gets up the same way twice running, reaches `StrikeReach` 200 and stuns players on a hit. Rebounds are 0.3 s (jab) / 0.6 s (smash); a shield's guard pool is 3x its Defence (`JeebItems::GuardPool`). In MoveLab every move hits other players (PvP test). A payoff-matrix model of the four options (scratch, PowerShell fictitious play) settled at attack 64%, shield 26%, kick 11%; the sweep is for punishing kicks and catching get-ups. Test pictures: `-ShotMove=sweep`, `kicksweep` (log JEEBSWEEP gives the tip height).

Third pass (owner, 2026-10-31): a kick that lands (`KickLanded`, server, multicast `MulticastKickLanded`) plays the rest of itself `KickLandedSpeed` (2.2x) faster and the low sweep may cut it short at once (`StartSweep`; a wheel-down during the kick is buffered in `QueuedSweep`; `ServerAttack` lets that combo through its rate and end-lag checks; the leg eases out over 0.1 s, `KickFade`). The dash attack (`EAtkStyle::Dash`, sprinting forward + click with a sword, `Interact`): a lunge with the blade stabbed straight out (key poses `Dash` in PoseArms keyed by `DashU`, legs in PoseKick), `DashLunge` 1100 cm/s, active 0.11-0.28 s, smash boxes, damage / stun / push of a smash charged `DashCharge` 0.2, end lag `DashLag()` = a smash's, rebounds like a smash. R skips slots without a weapon. Test pictures: `-ShotMove=dash`, `kickcombo` (with `-LabGuardFirst -LabKnight=150`).

## Bow and arrows (2026-10-31, Breath of the Wild style)

`KnightCharacterBow.cpp`. The bow is two-handed now (Kinds.csv: no shield with it) and held in the LEFT fist on `BowHold` (RebuildHeld; its straight string `BowString` hides while drawn and `BowBits` draw the pulled string, the nocked arrow and its head). Drawing: half walking speed, facing the camera, camera boom 540 -> `BowCamLength` 220 with the socket 75 cm right (`TickBow`), reticle `AKnightHUD::DrawReticle`; the arrow flies from `ArrowStart` toward what is under the reticle (`BowAimDir`). Weapon switch, roll, kick, swing, hitstun, knockdown, climbing etc. cancel without shooting. Pose (`PoseBow`, end of PoseArms): closed-form arm turns (left arm straight along the aim with the bow upright; right arm a two-bone reach to the string, elbow out right and back), chest +55 degrees (side-on). ## Direction: online multiplayer (decided 2026-10-12)

The owner dropped the single-player story mode: Jeebsland is becoming an online game set up like RuneScape (many players in a shared world, server-owned characters, several world servers). Build everything with that in mind.
- Chosen path: Unreal dedicated server first; accounts are files on the server for now (a database service later). Done 2026-10-12: two players in one world; server-owned characters; accounts and saves; shared combat.
- The game map is `/Game/Field` (not Lvl_ThirdPerson). `ServerDefaultMap` points at it.
- `AKnightGameState` builds the world on EVERY machine (server and clients) from fixed random seeds; `AKnightGameMode` exists only on the server and just picks where players appear (`SpawnDefaultPawnFor`, a 2 m ring round the start). Purely visual actors (moon, night sky, bats, fireflies) are skipped on a dedicated server.
- ONE game, online first (owner, 2026-10-12): never build separate single-player behaviour. When something is removed or changed for online play, do the same in single player (e.g. the horse is gone from both until it is shared online). Single player in the editor is only a quick test of the online game.
- Rules for new code: anything that changes game state (inventory, XP, damage, drops, deaths, shops, the bank) must end up decided on the server (client asks via a Server RPC, server checks, state replicates back). Never trust the client. Don't use `GetPlayerPawn(this, 0)` / `GetFirstPlayerController()` for gameplay (there is no "player 0" on a dedicated server, and there are many players); only for purely local visuals, null-checked.
- What is shared now: movement; the look (`RepLook`, worked out by the server); the pack, gear, XP and money (owner-only replication of `USkillComponent`); swings (`ServerAttack` / `MulticastAttack`); stance flags (`RepMoveFlags`: crouch, guard, roll, slide, climb); health, guard, deaths and sacks (`ALootDrop` replicated); arrows and bolts (`AProjectile` replicated); the pen knight and scarecrows (spawned by the server only); rock and tree charges, store stock and cottage doors (lists in `AKnightGameState`); damage numbers (`MulticastNumber`).
- Movement: the knight never uses unshared world geometry as its movement base (`SetBase` override). The world is built separately on every machine, so the server could not name it and the client threw away every correction (the snap-back-to-spawn bug). Climbing: the client moves the knight and the server trusts its position until it is back on the ground (`ServerClimb`).
- NOT networked yet: cats, NPC animations and dialogue (local; the trades go through the server), sitting, time of day, the horse (removed). Single player keeps a local save (`JeebSave` slot); online characters live on the server (`Saved/Characters`).
- Test: see `Docs/HowToTest.md`. World servers: `Tools/HostWorlds.bat` (both) or `Tools/RunServer.bat <1|2> [debug]` (debug logs every position correction: big logs, only for chasing movement bugs). `-JeebAutoLogin=Name:Password:World[:new]` logs a test account in (headless tests: add `-nullrhi`).
